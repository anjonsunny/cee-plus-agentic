3 · Every node in detail — meaning · rules · example · the tools it uses

the stack, one place LangGraph orchestration — turns the flow into nodes + edges Qwen2.5-VL the subject model (the one under test) Qwen2.5 dialogue model — narration only llama3.1 judge — different family GroundingDINO box detector SAM masks Rulebook exact-key rule lookup Python deterministic code RAG · LlamaIndex+Chroma built but DORMANT — see notes
PerceiveperceiveMODEL
What it means. The model looks at the photo and lists what it sees — each entity, a one-word condition (its "state"), and a rough box. The only place raw seeing happens.
In the collapse scene: lists a man, a building, dust, people behind tape — states like trapped, collapsed, rising.
tools
Qwen2.5-VLthe vision-language model that looks at the image and writes the first entity list (via Ollama, local).
LangGraphholds this as the entry node; its output (raw entities) is written into RunState.
Repairrepair · Loop 1 · can repeat (cap 2)FLAG → fix
What it means. The first answer is often written wrong — a category instead of a noun, a made-up state word, a missing box, a person listed twice. Repair fixes how the answer is written, never what is in the scene.
The six checks it runs (P-rules)
P1family name as label — "vehicle" → asks for the specific noun, quoting the model's own description.
P2label out of vocabulary — unknown noun becomes "other", counted.
P3state out of vocabulary — made-up condition word → offers the allowed list, normal words first.
P4missing box — every entity needs a rough box to be grounded.
P5caption entity missing — the caption names something the list lacks → add it, or say you can't see it.
P6duplicate being — two boxes on the same person = one individual twice.
In the collapse scene: caption said "police officers" but the list said "person" (P5), and two boxes sat on each officer (P6). Repair fixed the labels and merged the duplicates.
"Isn't this just reflection? Why call it repair?" — same shape (find → ask model → recheck, capped), different target:
Repair = copy-editor (Stage 1)Fixes the FORM: real vocabulary word? one box each? no duplicates? Never disputes conclusions.
Reflect = fact-checker (Stage 2)Fixes the MEANING: is the judgment consistent? Does the reason match the role? DOES dispute conclusions.
Repair is about the record; reflection is about the judgement.
tools
Pythonthe P1–P6 checks run as deterministic code on the raw answer — no model needed to find a format break.
Rulebookthe broken check's name is the key; the rule's text (statement + why + example) is fetched by that exact key and quoted into the fix request.
RAG · LlamaIndex+Chromadormant here. A semantic version exists in rulebook_rag.py, but exact-key lookup is right for repair (the break already names the rule), so embeddings aren't used.
Qwen2.5-VLre-asked with the image to fix the wording; it may stand its ground.
LangGraphthe repair loop is a self-edge — repeat while not clean and repair_round<2.
Assembleground → mask → derive → mergeCODE
What it means. The detector snaps each rough box tight; SAM cuts the mask. Then two code-only fixes: a hidden hazard is derived, and any duplicate the model refused to merge is merged — each with a note.
In the collapse scene: no drowning, so no hazard derived — but the two officer duplicates the model kept are merged, leaving one box per human.
tools
GroundingDINOopen-vocabulary detector — takes the model's rough box + label and snaps a tight, accurate box to the real object.
SAMSegment Anything — cuts the pixel mask inside each box (for overlays and future editing).
Pythonthe two derivations (medium-bound hazard, duplicate merge) are deterministic, each writing a note into the record.
LangGraphone node; freezes the finished record into RunState.
VerdictverdictMODEL
What it means. Reading only the record (never the photo again), the model answers four things: disaster? how bad, 0–10? who is dangerous (threats)? who is in danger (at-risk)?
In the collapse scene: "Yes · building collapse · level 8 · dangerous: building_1 · in danger: person_1."
tools
Qwen2.5-VLused text-only here — it reads the record as text and answers. The image is deliberately withheld (that's the whole experiment).
LangGraphone node; writes result.assessment.
Measurechecks + probesFLAG + MEASURE
What it means. Double-check the answer two ways, without asking the model to re-judge: code rules hunt for contradictions, and a stability test asks the same question 5 more times.
The contradiction rules (S/G) — ★ = serious enough to justify a petition
S1verdict must agree with its level
S2 / S3"No" while danger exists ★ · "Yes" with nothing dangerous ★
S5a "dangerous" thing whose state isn't hazardous ★
S6a real hazard left out of the dangerous list
S7 / S8a hazard listed as victim · a threat whose reason describes a victim ★
G2 / G4"near a hazard" with none present · wrong at-risk kind
In the collapse scene: S6 fires — dust_1 is hazardous but missing from the dangerous list; probes flicker on the dust.
tools
Pythonthe S/G checks and the geometry box-math (who overlaps what) are pure code — fast, deterministic, no model.
Qwen2.5-VLthe 5 probes — the same verdict question re-asked at a little randomness (temp 0.7) to see how the answer wobbles.
Qwen2.5the dialogue model writes the plain-English "why it's unsure" — kept separate from the subject so the subject never grades itself.
LangGraphone node; writes violations and u_before.
Runoff judgerunoff · only if unsureADVISE
What it means. When the answer is genuinely split, a different AI picks between the model's own two most-common answers. A hint for reflection — it changes nothing itself.
In the collapse scene: not split enough → the runoff judge stayed out.
tools
llama3.1a judge from a different model family on purpose — so it isn't just echoing the subject's habits. Reads the two candidate answers, names the better fit.
LangGrapha conditional node — only entered when uncertainty is over the threshold.
Reflectreflect · can repeat (cap 2)FLAG → the model revises
What it means. Hand every problem back to the model to fix its own judgment. Quote the broken rule + evidence — never "you're wrong", never the answer. It fixes it, or keeps it and explains why.
What triggers a reflection
•any rule violation (always) · a shaky entity from the probes · a weak reason · the runoff hint
↺repeat? still problems AND fewer than 2 rounds → go again. A guard stops pressure from bullying a correct answer into flipping.
In the collapse scene: the S6 dust gap is shown with rule S6 → the model adds dust_1 to the dangerous list. Done in one round.
tools
Rulebookfetches the exact rule text for each surviving problem and quotes it into the prompt as the evidence (the "teach" half of one-law-two-engines).
RAG · LlamaIndex+Chromafuture. This is the one live-run spot semantic RAG could earn a place: surface rules the reasoning smells like it's bending, beyond the exact checks. Not built — a Stage-4 idea.
Qwen2.5-VLthe subject is re-asked to revise its own judgment — only it may change the answer.
Pythongathers the triggers and enforces the capitulation guard (evidence-framed, never "you're unstable").
LangGraphthe reflection loop is a self-edge — repeat while triggers remain and reflect_round<2.
Router — the petitiondetect_petition · fires at most oncere-open a step
What it means. Some problems can't be fixed by re-judging, because the mistake is further back — the facts are wrong, or Stage 1 missed something. The router decides whether to re-open an earlier step, and which. It can fire only once.
Step 1 — did a SERIOUS problem survive reflection?
Only the ★ leftovers count (a threat that isn't dangerous, a "disaster" with no danger, a victim-shaped threat) — or a Stage-1 caption complaint never settled. A wobbly level number does not count. Nothing serious left → done.
Step 2 — which step to re-open? (what those conditions mean)
no hazard in the record→RE-LOOK THE PHOTO
Plain meaning: the answer insists something is dangerous, but the record lists nothing dangerous at all — so Stage 1 probably missed it in the photo.
Example: a child is treated as endangered, but no pool or water was ever recorded — the danger source is missing → re-look.
caption ticket stood→RE-LOOK THE PHOTO
Plain meaning: in Stage 1 the caption named something the model never listed and refused to add even when asked ("ticket stood"). An unsettled disagreement about what exists → a seeing question.
Example: caption says "chemical spill", the model never listed a spill and wouldn't add it → re-look to settle it.
a hazard IS in the record, states look right→RE-ASK THE QUESTION
Plain meaning: the record already has the danger and the facts are fine — something just got filed in the wrong list. The photo isn't the problem.
Example: a trapped man put in the "dangerous" list instead of "in danger" → re-ask.
In one line: facts might be missing (no hazard, or an unsettled caption) → re-look the photo. Facts fine but mis-sorted → re-ask the question.
tools
Pythondetect_petition — pure code reads the surviving violations + the record and chooses the route. No model decides this.
LangGraphthis node IS a conditional edge — the 3-way branch. Making this branch explicit and inspectable is the single biggest reason to move onto LangGraph.
Route A · Re-look photorelook_image → cascadere-perceive
What it means. Look at the image again to settle a missing/unsettled fact. Only adds a thing if a second detector confirms it; never deletes what was there; then re-runs Stage 2 on the merged record.
tools
Qwen2.5-VLre-looks at the photo, shown its previous answer + the problem (non-leading; "unchanged if you stand by it").
GroundingDINOthe second witness — a new entity merges only if DINO also grounds it (guards against the model inventing a convenient object).
Pythonthe two-witness + no-erasure merge; omissions become recorded disputes.
LangGraphthe cascade back-edge → verdict; petition_used stops a second round.
Route B · Re-ask questionreask_question → ENDre-judge, fresh
What it means. The facts are fine, so ask the judgement question once more, fresh — no memory of the back-and-forth (that's what caused the slip). The photo and record are never touched.
tools
Qwen2.5-VLtext-only, one clean ask — previous answer + the problem shown, allowed to stand by it.
Rulebookquotes the offending rule alongside the problem.
LangGrapha leaf node → pairwise → END; record untouched.
Pairwise judgepairwise · only if the answer changedADVISE
What it means. At the end, if the answer changed, a judge compares before vs after (blindly) and says which is better. Pure scorecard — never alters the answer, skipped if only wording changed.
In the collapse scene: dust was added, so pairwise weighs before (building only) vs after (building + dust).
tools
llama3.1the different-family judge does a blind A/B — it doesn't know which is the newer answer.
Pythonthe substantive-change gate — skip if only the wording moved (so a tie never becomes noise).
LangGrapha conditional node just before END.

5 · What a node looks like — the body is our existing code

Now · plain Python

# reflection loop lives inside a function
for rnd in range(2):
    a, v = reflect_once(record, a, v)
    if clean(v): break
# the counter is a local variable

LangGraph · node + conditional edge

def reflect(state):
    a, v = reflect_once(state.record,
              state.result.assessment,
              state.result.violations)
    return {"result": merged,
            "reflect_round": state.reflect_round+1}

# the LOOP is now an edge:
edge: reflect → reflect  if triggers & round<2
edge: reflect → router   otherwise

Same reflect_once inside. The only change: read from state, return the delta, and the counter moves into the state object. The for-loop becomes a self-edge with a condition.

6 · Honest scope — what's surgery, what's free

⚠ real work

1Split the two loop bodies out. run_perception and run_assessment run the repair & reflection loops inside them; to make a loop an edge, its one-round body must become a node.
2Lift the counters & flags into RunState (the amber fields).
3The in-place mutators (derive_medium_hazards, enforce_kinds) must return their changed record as the node delta so checkpointing sees it.

✓ stays as-is

✓Every function body — perceive, one repair round, DINO/SAM, verdict, checks, probes, one reflect round, runoff, petition, pairwise.
✓PerceptionResult / AssessmentResult — become fields, unchanged.
✓The event flight-recorder, the UI (reads events), all 297 tests.
✓The pattern itself — state.py + graph.py already do this.

7 · How fine to cut the nodes

Option A · coarse — 3 nodes (perceive · assess · petition)
Wrap each whole function as one node; loops stay inside as Python. Cheapest, but the loops & route stay invisible — almost no gain over today.
Option B · at the branch points RECOMMENDED
A node exactly where control branches: perceive · repair · assemble · verdict · measure · runoff · reflect · router · relook · reask · pairwise. Linear steps (DINO→SAM) stay inside one node. The loops and the petition route become the real edges — the whole point — without exploding every mechanical step.
Option C · every step a node
Maximum inspectability, maximum churn. Overkill for now.

8 · How we'd do it safely

Build it as a separate graph_live.py next to the working pipeline — never edit the tested path. Behind a flag. Run all six scenes through both and prove they produce identical records and verdicts. Switch the UI over only once they match. Same Arm A / Arm B discipline, one level down: build alongside, verify equal, then adopt.
